# Acer H PRO Series 55" 4K Google TV (AR55GR2851UDPRO), India
# Built by Indkal on a MOKA (MK) platform: model R4G, device R4_GTV, Realtek RTD2851M, 2 GB RAM.
# Google TV 14 (SDK 34), firmware UKR1.260308.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/acer-h-pro-ar55gr2851udpro/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/acer-h-pro-ar55gr2851udpro/debloat.txt com.google.android.apps.tv.launcherx
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Stock launcher: com.google.android.apps.tv.launcherx. Live TV app: com.realtek.tv.
# USB debugging alone opened port 5555 on this firmware; no wireless pairing was needed.
# Nothing was disabled from the factory (pm list packages -d was empty).
#
# WARNING, checked on the TV over three reboots: this firmware puts every package back at each boot.
# The TV cold-boots on every power-on (settings global boot_count was 1139), and `pm disable-user` and
# even `pm uninstall -k --user 0` are both undone. Only com.apps.mk.wd and
# com.realtek.leanbacklauncher.partnercustomizer stay disabled, plus the animation scales (settings).
# Re-run this list after each power-on if you want the rest off for that session.
# Why (checked 23 Oct): it is not a reset. After boot most packages read enabled=1 (explicitly ENABLED,
# not 0/default) in `dumpsys package`, so a vendor routine turns them back on. RtkKeyInterceptService_RTK
# and RtkMenuSliceProvider carry an `enableBasicModeApp` list (KATNISS, TVMANAGER, FASTCASTTV,
# TVMEETINGMODE, S_CHANNEL, OTA, RCUUPDATE, YouTube, Netflix, Prime) tied to Google TV "Basic mode", and
# com.apps.sys has a HideApkReceiver. Both run as android.uid.system, so this cannot be stopped without root.
# What helps and is cheap to redo: the real lag here is RAM. 2 GB with YouTube (~250 MB), SonyLIV and
# Netflix (~90 MB each) idling for the home rows had kswapd0 at ~97% CPU. Blocking background runs keeps
# the apps working when opened:  cmd appops set <pkg> RUN_ANY_IN_BACKGROUND ignore   (undo: allow).
# With this list plus that, MemAvailable went from ~307 MB to ~620 MB and ~200 MB of swap came back.
#
# Working setup (23 Oct, survived a reboot): the launcher's debloat keeper (config.xml keeper_*) reconnects
# to the TV's own adb on 127.0.0.1:5555 about 20 s after each boot and re-disables this list, re-applies the
# background block and keeps Home. Leave USB debugging on and accept its "Allow USB debugging?" prompt once.
# Home: launcherx (priority 2) and setupwraith's RecoveryActivity (priority 1) out-rank any third-party HOME,
# Android resolves Home by priority before the user's choice, and the shell may not disable single
# components ("Shell cannot change component state"). So launcherx stays enabled and the launcher's
# HomeKeyService takes KEYCODE_HOME and covers launcherx whenever it comes to the front. Install with
#   launcher\build-and-install.ps1 -StockLauncher none -InputKeyService -HomeKeyService
# The script's final "Home resolves to launcherx" check fails here by design; enable the two services
# (enabled_accessibility_services) by hand if it stops before them.
# The launcher half is NOT safe here: com.google.android.tungsten.setupwraith comes back enabled at
# boot, its RecoveryActivity takes Home and system_server crash-loops (TV drops off Wi-Fi) until
# `pm enable --user 0 com.google.android.apps.tv.launcherx`. Keep launcherx and use Google TV's own
# "Apps only mode" (Settings > Accounts & sign-in > your account) to drop the ads and recommendations.
